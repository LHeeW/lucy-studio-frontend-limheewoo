## 구현 범위

**관심 화면**
- [X] 관심종목 각 행에 정보 표시
- [X] 등락에 따라 색상 변경 (상승/하락/보합)
- [X] 새로고침 구현
- [X] 하단 탭 전환
- [X] 스켈레톤 구현
- [X] 빈 상태 화면 구현
- [X] 정렬 기능 구현 (현재가,등락률,가나다)

**검색 화면**
- [X] 검색창 구현
- [X] 검색 결과 정보 표시 (검색어와 일치시 하이라이트)
- [X] 관심 아이콘 구현 (즉시 반영)
- [X] 검색 결과 종목 클릭시 상세 화면으로 이동
- [X] 초기 상태 구현
- [X] 검색 결과 없을 때 상태 구현
- [X] 디바운스 구현 (300ms)

**종목 상세**
- [X] 상단에 뒤로 가기, 종목명, 관심 등록 버튼 구현
- [X] 현재가와 전일 대비 등락 표시 구현 (방향 아이콘 포함)
- [X] 요약 카드 구현
- [ ] 요약 카드의 내용은 일별 시세가 아닌 실시간 시세를 바탕으로 우선 구현하였습니다.
- [ ] 캔들 차트, 기간 탭, 일별 시세, 요약 카드(실시간 -> 일별)의 내용은 아직 구현하지 못했습니다.
- [ ] 일별 시세 HTML 페이지 제공이 중단되어 일단 보류하고 넘어간 뒤 과제2까지 모두 완수 한 뒤 시간이 남으면 추가 제공 받은 api로 구현해보도록 하겠습니다.

**상태 동기화**
- [X] 관심 상태가 바뀌면 관심, 검색, 상세 화면의 별 아이콘 모두 변경
- [X] 검색 직후에도 현재 관심 상태가 결과에 반영
- [X] 검색 화면에서 관심 등록한 종목이 관심 화면 목록에 반영
- [X] 상세 화면에서 관심을 해제하고 돌아오면 목록에도 반영

## 기술 선택과 이유

- 주요 패키지
  - dio ( api 연결용 )
  - provider ( 상태 관리용 )
  - intl ( 금액 표시용 )

- 상태 관리, 아키텍처 패턴, 폴더 구조
  - 상태 관리
    - provider 통해 전역으로 상태를 관리했습니다.
    - 단순 과제가 아니라 추후의 확장을 생각한다면 bloc이나 riverpod를 선택했을 수도 있지만 현재의 CRUD 구현하기에는 provider가 최적이라고 판단되어 선택했습니다.
    - getx는 편리하기는 하지만 데이터 흐름을 추적하기에 까다로워 디버깅에 문제가 되어 배제했습니다.

  - 아키텍처 패턴
    - MVVM 패턴을 적용했습니다.
    - UI와 비지니스 로직을 분리해서 가독성과 유지보수가 향상되고
    - 외부에서 받은 데이터를 model을 통해 가공해주고 provider를 통해서 ui에 뿌려주는 형식으로 다양한 곳에서 재사용도 용이하고
    - 상호간의 간섭이 없기에 데이터 흐름 파악이나 로직 수정에 간편하여 이 패턴을 적용했습니다.
    - 
  - 폴더 구조
    ```text
    lib/
      main.dart                             앱 진입점
      models/                               model 정의
        realtime.dart                       실시간 시세 모델
        stock_metadata.dart                 종목 메타데이터 모델
        stock.dart                          검색된 주식 모델
        watchlist_item.dart                 구독 모델 (realtime + stock)
      services/
        naver_api_service_mock.dart         목데이터 받는 용도 
        naver_api_service_utils.dart        실제데이터와 목데이터에서 중복되는 코드 함수화
        naver_api_service.dart              실제데이터 받는 용도
      viewmodels/
        main_view_model.dart                메인 화면 탭 바 상태관리
        searchlist_view_model.dart          검색 화면 상태관리
        stock_metadata_view_model.dart      상세 화면 상태관리
        watchlist_view_model.dart           구독 화면 상태관리
      views/                                각 폴더별 index.dart가 메인 화면
        searchlist_screen/                  검색 화면 구현
        stock_detail_screen/                상세 화면 구현
        watchlist_screen/                   구독 화면 구현
        main_screen.dart                    탭바 구현
      widgets/                              스켈레톤UI, 재사용되는 UI 구현
    assets/
      mock/                                 응답 샘플을 저장
    fetchmocks/                             목데이터 생성을 위한 코드
    ```
  
  - 차트 처리 방식
    - 아직 구현하지 않았지만 추후에 구현하게 된다면 패키지를 사용하여 구현할 예정입니다.
  
  - 디자인 토큰은 지정해준 것 외에는 사용하지 않았습니다.

## 직접 판단한 부분과 이유

- 토스트 노출 시간과 사라지는 방식
  - 토스트는 300ms의 짧은 시간만 유지됩니다.
  - UX측면에서 화면에 단순 관심 등록/해제 문구를 장시간 토스트 메세지로 보여줄 경우 답답할 수 있다고 판단했습니다.
  - 생성과 제거는 위아래로 자연스럽게 올라왔다가 사라지는 방식을 적용했습니다.

- 로딩 / 네트워크 에러 / 긴 종목명 오버플로 처리
  - 로딩
    - 검색어를 입력할 때 CircularProgressIndicator()를 이용하여 로딩 중이라는 표시를 해줬습니다.
    - 데이터를 표시할 때는 ListviewBuilder의 snapshot을 이용하여 스켈레톤 UI가 뜨도록 구현했습니다.
    - 각각 로딩이 다른 방식인 이유는 검색어는 실시간으로 상호작용하고 있다는 느낌을 주기 위함이고 스켈레톤UI는 데이터의 흐름을 살리기 위함입니다.

  - 네트워크 에러
    - 화면에서 오류를 표시해주거나 데이터를 받아오지 못한 경우에는 해당 데이터에 `-`표시로 없음을 나타내줬습니다.

  - 긴 종목명 오버플로 처리
    - 놓친 부분입니다.
    - 추후에 시간이 된다면 오버플로된 부분을 `...`으로 처리하거나 아니면 전체 이름이 다 뜨게하면서 애니메이션 효과로 좌우로 슬라이드되도록 구현하겠습니다.

- 시세를 못 받은 행이 있을 때의 정렬 처리
  - 놓친 부분입니다.
  - 추후에 시간이 된다면 UI에선 `-`으로 보이게 하고 비지니스 로직에선 0으로 처리하여 후순위에 두도록 구현해보겠습니다.

- Figma와 다르게 구현한 부분
  - Search Icon이 약간 다릅니다.
  - 빈 화면, 검색어를 찾지 못했을 때 문구의 위치가 약간 다릅니다. ( 과제2를 완료하고 시간이 된다면 수정 하겠습니다. )

## 막혔던 지점과 어떻게 접근했는지

  - 구독 리스트를 보여줄 때 주식 정보와 실시간 시세를 합쳐서 보여줘야 되었습니다. 주식정보와 실시간 시세를 합친 하나의 model을 만들고(`watchlist_item`) 구독 버튼을 눌렀을때 주식의 코드와 실시간 시세의 코드가 일치하는지 여부를 판단하여 새로운 리스트에 넣어주도록 설계하였습니다.
  - 일별 시세가 기존에 주어졌던 api로 접근이 불가능하여 임시방편으로 실시간 시세의 정보를 주입해 놓았습니다. 과제2를 마친 후 시간이 된다면 새롭게 받은 api를 토대로 작업을 마무리 하도록 하겠습니다.
